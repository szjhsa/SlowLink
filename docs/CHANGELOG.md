# 更新日志

## [未发布]

- 主体增加消息发布时间、转发来源时间和队列最大等待时间门，断线补收的旧任务不会继续转发。
- 多目标发送增加逐目标 `pending/sent/failed` 状态，部分成功或进程中断后不会再向已完成目标重发。
- 插件临时重复事件增加 5 分钟过期、总事件上限和单身份上限，避免长期运行内存增长。
- 插件新增 `format_gates` 协议，支持 `all`、`any`、`exclude`、`regex_any` 和 `regex_min_hits`；仅对对应规则类型生效。
- 插件新增占位码、全同字符、连续字符、循环字符和示例码护栏。
- 修复多行文本中字段码与 Whitelist 混在一起时生成错误 Whitelist 身份的问题。
- 修复抽奖活动说明中出现“中奖信息截图”时被误判成开奖结果的问题。
- Register/Renew 完整码规则支持 `6.`、`12、` 等列表序号前缀，并同步迁移原规则策略。
- 注册/开注公告把“开启时间、开放时间、开注时间”等加入去重身份，不同开注时间不再互相拦截。
- Register/Renew 掩码码中的 `*` 按猜码内容处理，`kLa**guKMq` 会还原为完整身份 `kLaguKMq`，不再只截到星号前。
- 掩码码会注册有边界、有数量上限的通配身份，后续猜出的完整码可以命中同一去重记录；支持先完整码后掩码码，并区分 Telegram Markdown 加粗星号。
- 通配去重职责重新分层：插件输出通用 `wildcard:` 业务身份，主体只负责匹配、Redis、TTL 和数量上限，不再硬编码 Register/Renew 前缀。
- watchdog 改为“持续高 CPU + 业务停滞”双条件，正常高负载但仍在处理消息时不会误重启。
- 单条队列任务和失败队列重试增加最大处理时间，超时后取消任务并记录卡死原因。
- 新增 `JOB_MAX_PROCESSING_SECONDS`，默认 180 秒，设为 0 可关闭；业务进度、收到消息时间和卡死状态写入 Redis。
- 修复 `;;` 合并规则的策略展示：各分段策略完全一致时，整条规则会正确继承并显示该策略。
- 修复抽奖过期门跨类型误伤：只有实际命中抽奖业务规则时才检查截止时间，注册公告中的“截止时间”不会再被当成过期抽奖。

## [1.1] - 2026-10-01

- 当前主线和插件版本统一改为 1.1。
- 包含插件类型、规则生成、去重兼容、CPU 超时保护和插件关闭回退的全部修复。
- 发布构建只允许清理仓库 `dist`，拒绝删除其它已存在目录。
- 插件安装会预编译规则正则，并使用唯一临时目录；插件切换失败时自动回滚。
- 修复插件类型标签转义和 URL hash 直达页面，统一简化版控制台。
- 抽奖参与人数等动态指纹改由插件 `dynamic_line_patterns` 定义，跨模板冲突保留正文去重 key。
- 新增 `code_identity` 插件协议，支持掩码/明文注册码的双向识别，核心仅在发送成功后提交身份。
- 插件改为只做码识别、分类和去重增强，不再独立触发转发；没有用户正则时不会自动匹配业务消息。
- 插件明确判定为说明文或开奖结果时，即使用户正则命中也不会转发。
- 清理插件中未接线的旧去重执行引擎、码规则 CRUD 诊断函数，以及主体未调用的文本压缩函数；运行行为不变。
- 插件格式门在规则未绑定策略时，会使用插件实际识别出的业务类型继续校验，避免残缺抽奖模板绕过否决。
- 修复失败队列重试超时或取消时已弹出任务不回队、可能丢消息的问题。
- 修复会话刷新在读取旧缓存异常时引用未初始化变量的问题。
- 移除无效的“极速通道 / 单独触发”界面开关和过时文案，明确插件仅辅助识别、用户正则仍是唯一触发器。
- 清理未使用的抽奖键模式和相似度默认配置。
- 清理主系统已不使用的旧去重模式参数，保留兼容参数入口但不再参与运行。

## [1.0] - 2026-08-15

- 首个正式纯净版：主程序不再内置规则插件，安装后为纯净引擎，插件由用户上传。
- 插件支持上传、启用、停用、删除、同 ID 更新，上传插件持久化保存，更新后不丢失。
- 正则、排除文本、码识别、去重、账号/转发/监听、备份恢复、日志和 watchdog 全面整理。
- 支持正则单条启用/停用、修改后台密码、登录失败锁定、配置导入失败自动回滚。
- 正则列表按钮在桌面和手机端保持紧凑布局，长正则自动换行不遮挡操作按钮。
- Caddy 异常退出或配置损坏时会自动用当前配置重建，更新脚本也会重建非运行状态的 Caddy。
- Caddy 增加 Docker 健康检查，`manage.sh status` 直接显示代理健康状态。
- 新增 `manage.sh doctor` 一键检查容器、健康、插件、磁盘和公网访问。
- Redis 增加 256MB 内存上限和 `volatile-lru` 淘汰策略。
- watchdog 每天自动清理 Docker 构建缓存；备份目录只保留最近 7 份。
